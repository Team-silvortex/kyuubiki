daji 3.5.0

Early Daji prioritizes hardening an agent-driven industrial research system: bounded studies, real execution, numerical trust, safe recovery, and reproducible evidence rather than a larger feature catalog.

The current development point is daji 3.5.0. Source package metadata targets 3.5.0; the last locally built and installed desktop/runtime baseline remains daji 3.4.0. This checkpoint does not rebuild or install binaries; public distribution remains a separate, evidence-gated action. Daji succeeds the moxi 2.x development line; historical qualification keeps its original version and scope.

This is the short Hub mirror of the central chapter docs/book-ch02-version-line.html.

What this line means

  • Keep the inherited baseline contract-driven instead of returning to prototype sprawl.
  • Prefer confidence and coherence over raw feature-count inflation.
  • Research agents use Headless SDKs; Rust Agents execute admitted tasks. Neither bypasses caller-owned approval or quality gates.
  • Keep Workbench first-class for modeling, review, and human takeover; do not require GUI setup for Headless research.
  • Expand capabilities when they remove a demonstrated research-loop blocker.

Current 3.5.0 checkpoint

  • Native execution advances only from valid completion receipts and actual source bindings. Risk labels and approval gates remain contract-owned.
  • Job waits validate the requested identity; result reads require completed jobs with explicit object results.
  • Lost or invalid write acknowledgements stop as unknown outcomes without replay. Inspect server records before authorizing continuation.
  • Complete 2xx submissions also require usable job IDs and consistent public status. Malformed receipts stop before later work; explicit failed/cancelled jobs remain known failures.
  • Native library writes validate usable identities and requested objects/parents before advancing. Registered FEM saved-version jobs retain their server-side version association.
  • Saved model/version reads match their requested identity and parents before computation. Mixed inline/reference inputs stop; native mesh fallback preserves verified context without inventing a saved version for a mutable model.
  • Native job reads enforce explicit project/version/case hints and reject ambiguous options. Saved-version solve/wait carries its version constraint through result reading; read failure never authorizes automatic replay.
  • Native submissions match transmitted project/version association before accepting job bindings. Orchestra rejects contradictory explicit pairs before creating work; uncertain replies do not authorize replay.
  • Single-job queries validate identity, state and explicit association before returning bindings. Failed/cancelled jobs remain inspectable; successful observation is not completed computation.
  • Native HTTP reads and upload receipts share wire/header limits and nonrenewable network deadlines. Oversized writes remain unknown without replay; large result reads retain a separate budget. Full parsed values and raw/result mirrors are not a process-wide memory cap.
  • Native batch bindings retain only later-referenced outputs and move each field on final use. Fanout and report shapes remain unchanged; real SDK/CLI result-to-version chains preserve full arrays without repeating computation. Live branches and public result normalization still allocate.
  • Native job/result and combined solve/wait normalization avoid extra envelope copies, retaining independent public mirrors and unchanged receipt/completion gates. Real SDK/CLI result persistence is checked without extra computation; pointer tests are not RSS or scale qualification.
  • Native inline JSON retains one bounded encoded buffer, sends borrowed header/body vectors and releases the body before response reading. Exact-size oversize rejection is pre-connect; real SDK/CLI multilingual notes are preserved. This is not a total RSS/CPU bound or scale claim.
  • Native reports move eligible owned fields, retaining complete binding originals and independent previews. Sampling releases source capacity without changing summary or failure rules. Real SDK/CLI samples and Unicode prefixes match full stored data; no aggregate RSS/scale qualification follows.
  • Native Headless CLI JSON uses a 64 KiB buffer and staged single-file replacement, with no old-report backups.
