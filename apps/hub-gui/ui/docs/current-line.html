daji 3.0.0

Early Daji prioritizes hardening an agent-driven industrial research system: bounded studies, real execution, numerical trust, safe recovery, and reproducible evidence rather than a larger feature catalog.

The current development point is daji 3.0.0. Daji succeeds the moxi 2.x development line; historical qualification keeps its original version and scope.

This is the short Hub mirror of the central chapter docs/book-ch02-version-line.html.

What this line means

  • Keep the inherited baseline contract-driven instead of returning to prototype sprawl.
  • Prefer confidence and coherence over raw feature-count inflation.
  • Research agents use Headless SDKs; Rust Agents execute admitted tasks. Neither bypasses caller-owned approval or quality gates.
  • Keep Workbench first-class for modeling, review, and human takeover; do not require GUI setup for Headless research.
  • Expand capabilities when they remove a demonstrated research-loop blocker.

Current 3.0.0 checkpoint

  • GUI actions and backend calls should form complete, recoverable user journeys.
  • Native usability probes now execute the 8 blocking paths as baseline evidence without relying on legacy Node shims.
  • Pwdt becomes the deterministic frontend automation surface for product-owned shells.
  • The coverage tensor is the first planning gate for weak coordinates.
  • Component integrity, language packs, update visibility, and docs mirrors move with the current line.
  • Prior macOS and Ubuntu installed-startup evidence is retained; new Daji packages require their own platform checks.
  • Numerical maturity remains scoped by operator and evidence, not by the product version.
  • The planned public channel is Reddit; this transition does not waive readiness gates or publish packages.
