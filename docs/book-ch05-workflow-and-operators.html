Workflow and operator philosophy

Kyuubiki is moving beyond isolated single operators. The workflow direction is shader-like and neural-network-like composition: operators connected through a stable cross-operator data contract.

Back to book Previous chapter Next chapter

Core workflow ideas

  • Workflow graph growth should be intentional, not ad hoc.
  • Dataset transport should be portable and contract-driven, with an ONNX-like spirit.
  • Operator library ownership remains centralized instead of replicated to every agent.

Why this matters

Once operators can compose reliably, the system can grow toward larger simulation authoring flows without losing headless repeatability or distributed execution discipline.

Rich descriptions, stable execution IR

Material frame tasks may describe rectangle, I-section, circular, hollow-box, T-section, or custom layered sections. The runtime validates and compiles every description into the same centered fiber representation before the Agent engine executes it. This keeps authoring convenient without coupling the solver to UI-specific section objects. 

{
  "kind": "layered",
  "layers": [
    {"y_min": -0.30, "y_max": -0.10, "width": 0.05, "fiber_count": 4},
    {"y_min": -0.10, "y_max": 0.15, "width": 0.02, "fiber_count": 5},
    {"y_min": 0.15, "y_max": 0.30, "width": 0.10, "fiber_count": 3}
  ]
}

Layers may touch or remain separated, but cannot overlap. Area, centroid, and second moment must agree with the parent frame element. Geometry alone does not infer a composite; material assignments use the explicit ID catalog shown below. 

{
  "kind": "polygon",
  "vertices": [
    {"y": -0.20, "z": 0.00}, {"y": -0.20, "z": 0.05},
    {"y": 0.10, "z": 0.05}, {"y": 0.10, "z": 0.20},
    {"y": 0.20, "z": 0.20}, {"y": 0.20, "z": 0.00}
  ],
  "fiber_count": 16
}

Polygon sections accept one simple finite ring, including concave profiles and either vertex orientation. Self-intersection, holes, multiple rings, and composite fiber materials are not silently inferred.

Material IDs are resolved before execution and returned in result diagnostics. The optional quadratic residual-stress template is projected against constant and linear section modes, so its discrete axial force and bending moment vanish before the requested peak magnitude is applied. Explicit fiber stresses and templates are mutually exclusive, and every generated stress must remain inside its phase yield surface. Individual phases may also opt into bounded equivalent-plastic-strain damage. The nominal stress and consistent tangent degrade while damage remains monotonic and frozen during elastic unloading; results expose maximum damage and damaged fiber point count. The frame-fiber scope still assumes perfectly bonded uniaxial fibers. A separate solve.cohesive_interface_1d operator now evaluates bilinear opening, damaged unloading/reloading, complete tensile failure, and compressive closure as a composable history contract. A four-node solve.cohesive_interface_2d element kernel now projects upper/lower displacement jumps into local opening and shear, rotates tractions back to global coordinates, and emits exactly self-balanced nodal forces. Two-point Gauss integration retains independent history at each point and emits a complete 8 x 8 consistent material tangent. The separate solve.cohesive_interface_mesh_2d operator now resolves a material catalog and assembles multiple kernels into an incremental Newton equilibrium system. Loads and optional non-zero constrained displacements advance proportionally, so retained monotonic paths can cross peak traction and reach complete separation. Explicit control histories additionally support cyclic and non-proportional constrained paths with per-step traction, reaction, displacement, residual, and directional-damage summaries. Trial Gauss-point histories are committed only after convergence; failures retain the previous state and expose a reason. Optional two-node linear component connector springs now share the global DOF assembly with cohesive elements. A retained series closed form verifies common equilibrium, displacement decomposition, connector force, and strain energy through solver, Agent RPC, and workflow paths. Small-displacement linear 2D host trusses now reuse the public truss protocol and contribute physical EA/L stiffness to that same global system. A second retained series reference verifies truss strain, stress, axial force, energy density, and common equilibrium. This is the first real structural host element. Constant-strain plane-stress triangles now add the first continuum host through the public plane-element protocol; a prescribed-apex series reference verifies analytic stiffness partition, common force, continuum stress, and energy. Fully integrated plane quads and Euler-Bernoulli frame hosts now use the same sparse Newton assembly. A separate solve.cohesive_interface_mesh_3d operator provides a true six-node triangular surface with two tangential and one normal history at each of three integration points. Optional tetrahedral solids reuse the native solve.solid_tetra_3d element kernel and share the same global DOFs, residual, and tangent. Retained references cover uniform opening, unloading damage, rigid coordinate rotation, interface/solid equilibrium, Agent RPC, Engine Workflow, headless HTTP submission, and a 1,440-DOF sparse model. Shell hosts, higher-order faces, coupled mixed-mode laws, and scalable sparse-indefinite factorization remain open. Post-peak continuation, coupled mixed-mode delamination, friction, three-dimensional composite constitutive behavior, and arc-length continuation remain future capabilities.

Summary cross-check gates

Connect reference and candidate summary objects to the left and right inputs of transform.validate_summary_tolerance. Its kyuubiki.summary_tolerance_validation/v1 report can feed transform.compose_quality_objective or the Rust Headless SDK material quality gate. A completed node is not itself proof of a passed comparison or a physically converged solution. 

{
  "fields": ["peak_temperature_c"],
  "absolute_tolerance": 0.05,
  "relative_tolerance": 0.001,
  "fail_on_missing": true
}
  • The example is node configuration. Tolerances must be finite and nonnegative; zero is valid. A field passes if either its absolute or relative error is within tolerance. Omitted tolerances default to 1e-9 absolute and 1e-6 relative.
  • An explicit field list must be nonempty, with unique nonblank strings. Without it, numeric keys from either summary are selected in sorted order. One-sided numeric fields and numeric/type changes are recorded as missing evidence, not silently excluded.
  • At least one field must actually be compared before the report can pass. fail_on_missing: false allows partial evidence, not an empty comparison. Missing fields block by default.
  • Present null or wrongly typed options are configuration errors; they do not fall back to defaults. An omitted or null whole config uses defaults. An unrepresentable error fails with the field name, rather than producing a null error metric.
  • Quality consumers require an explicit pass, a positive checked count, zero failures, and missing counts consistent with the missing-field policy. Nonempty or malformed failure details also block. Invalid success metadata remains available for repair planning.
  • Invalid configuration and non-finite errors fail the workflow by default. With an explicit on_error: "skip" recovery policy, the failed node retains its diagnostic, dependent work is skipped, and independent branches may finish. That is recovery, not successful validation.

This gate checks summary agreement, not independent scientific correctness. Model assumptions, convergence, reference quality, and physical validation still need their own evidence.

Quality ranking and incomplete evaluations

Quality scores are nonnegative penalties, not arbitrary signed physical quantities. transform.compose_quality_objective rejects non-finite arithmetic, negative scores, malformed configured numbers, and overflowing aggregate counters with the affected source and field. Valid zero weights and large finite values remain supported. Explicit blocking terms override a source's claimed ready flag.

Use an explicit qualities object when a candidate also carries metadata. Every named quality summary must be an object; missing or malformed sources cannot silently disappear. Candidate IDs must remain unique, including automatically assigned array IDs.

  • transform.rank_quality_candidates retains evaluable candidates in ranking. Each rejected evaluation is recorded in rejected_candidates with its candidate_id and error.
  • candidate_count counts ranked candidates; input_candidate_count includes rejected candidates. rejected_candidate_count counts the rejection records. ranking_complete is false if any evaluation was rejected. Completeness does not imply that every ranked candidate is ready.
  • If all evaluations are rejected, ranking fails with their count and the first named failure reason. It does not invent a winner.
  • transform.prepare_quality_next_round_request refuses missing, malformed, or negative selected scores instead of treating them as zero. Supplied completeness counters must agree with the ranking and rejection arrays.
  • Incomplete evaluation produces replan with a repair_rejected_candidates hint and retained rejection details. Even require_ready: false only permits an unready candidate to continue; it cannot satisfy the stop condition.
  • An incomplete ranking disables downstream quality-sweep planning and expansion. The result contains zero cases, keeps sweep_action: replan, and exposes sweep_blocking_reason: candidate_evaluation_incomplete plus source_rejected_candidates. Repair those inputs and rerun ranking before generating another parameter sweep.

A disabled sweep awaiting repair is not a converged or completed study. These checks preserve numerical and workflow integrity; they do not replace independent physical validation.

Parameter sweep budget boundaries

Planning, materialization, and expansion share the same count rules. max_cases is a nonnegative whole count; zero allows no cases. samples_per_axis must be at least two and max_axes at least one. Exact floating representations such as 4.0 are accepted and emitted as integers. Null fields, strings, negative or fractional counts, and out-of-range counts are errors, not requests to use a larger default. Defaults apply only when a field is absent.

  • The planner validates every search-space axis, selects axes by focus and axis budget, then checks the Cartesian product with overflow detection before allocating range samples. Malformed or empty axes cannot silently shrink the search. Truncated axes remain visible in the budget's usable count and follow-up recommendation.
  • Over-budget plans are diagnostic-only. Their axes contain value_count and values_deferred: true, without a values array. This avoids generating large sample arrays that would immediately be rejected.
  • For an executable plan, materialization and expansion verify the actual axis product against the effective limit. Stale estimates and a claimed ready flag cannot authorize excess cases. Lowering the limit in either stage takes effect before case generation.
  • A quality-sweep budget block returns zero cases with expansion_budget_ready: false and expansion_blocking_reason: case_budget_exceeded. Candidate identity, estimated count, and budget diagnostics remain available. Raising a downstream limit does not release an upstream block: adjust the planning inputs and build a new plan.
  • Direct transform.expand_parameter_sweep requests above their limit return an error. Invalid counts and arithmetic overflow also return errors rather than partial sweeps or wrapped counts. An explicit workflow recovery policy can preserve independent branches while retaining the failed-node diagnostic.

Billion-sample deferred-plan tests validate rejection without sample allocation; they do not demonstrate billion-case simulation capacity. Range interpolation preserves finite endpoints even when subtracting the two endpoints directly would overflow.
