Workflow and operator philosophy

Kyuubiki is moving beyond isolated single operators. The workflow direction is shader-like and neural-network-like composition: operators connected through a stable cross-operator data contract.

Back to book Previous chapter Next chapter

Core workflow ideas

  • Workflow graph growth should be intentional, not ad hoc.
  • Dataset transport should be portable and contract-driven, with an ONNX-like spirit.
  • Operator library ownership remains centralized instead of replicated to every agent.

Why this matters

Once operators can compose reliably, the system can grow toward larger simulation authoring flows without losing headless repeatability or distributed execution discipline.

Rich descriptions, stable execution IR

Material frame tasks may describe rectangle, I-section, circular, hollow-box, T-section, or custom layered sections. The runtime validates and compiles every description into the same centered fiber representation before the Agent engine executes it. This keeps authoring convenient without coupling the solver to UI-specific section objects. 

{
  "kind": "layered",
  "layers": [
    {"y_min": -0.30, "y_max": -0.10, "width": 0.05, "fiber_count": 4},
    {"y_min": -0.10, "y_max": 0.15, "width": 0.02, "fiber_count": 5},
    {"y_min": 0.15, "y_max": 0.30, "width": 0.10, "fiber_count": 3}
  ]
}

Layers may touch or remain separated, but cannot overlap. Area, centroid, and second moment must agree with the parent frame element. Geometry alone does not infer a composite; material assignments use the explicit ID catalog shown below. 

{
  "kind": "polygon",
  "vertices": [
    {"y": -0.20, "z": 0.00}, {"y": -0.20, "z": 0.05},
    {"y": 0.10, "z": 0.05}, {"y": 0.10, "z": 0.20},
    {"y": 0.20, "z": 0.20}, {"y": 0.20, "z": 0.00}
  ],
  "fiber_count": 16
}

Polygon sections accept one simple finite ring, including concave profiles and either vertex orientation. Self-intersection, holes, multiple rings, and composite fiber materials are not silently inferred. 

{
  "section_library": {
    "kind": "layered",
    "layers": [
      {"y_min": -0.20, "y_max": 0.00, "width": 0.10, "fiber_count": 4, "material_id": "soft"},
      {"y_min": 0.00, "y_max": 0.20, "width": 0.10, "fiber_count": 4, "material_id": "stiff"}
    ]
  },
  "fiber_materials": [
    {
      "id": "soft",
      "youngs_modulus": 7.0e10,
      "yield_strength": 1.0e8,
      "hardening_ratio": 0.02,
      "damage": {
        "onset_equivalent_plastic_strain": 0.001,
        "failure_equivalent_plastic_strain": 0.02,
        "maximum_damage": 0.4
      }
    },
    {"id": "stiff", "youngs_modulus": 2.0e11, "yield_strength": 5.0e8, "hardening_ratio": 0.02}
  ],
  "residual_stress_template": {
    "kind": "self_equilibrated_quadratic",
    "peak_stress": 5.0e7
  }
}

Material IDs are resolved before execution and returned in result diagnostics. The optional quadratic residual-stress template is projected against constant and linear section modes, so its discrete axial force and bending moment vanish before the requested peak magnitude is applied. Explicit fiber stresses and templates are mutually exclusive, and every generated stress must remain inside its phase yield surface. Individual phases may also opt into bounded equivalent-plastic-strain damage. The nominal stress and consistent tangent degrade while damage remains monotonic and frozen during elastic unloading; results expose maximum damage and damaged fiber point count. The frame-fiber scope still assumes perfectly bonded uniaxial fibers. A separate solve.cohesive_interface_1d operator now evaluates bilinear opening, damaged unloading/reloading, complete tensile failure, and compressive closure as a composable history contract. A four-node solve.cohesive_interface_2d element kernel now projects upper/lower displacement jumps into local opening and shear, rotates tractions back to global coordinates, and emits exactly self-balanced nodal forces. Global nonlinear interface-mesh assembly, coupled mixed-mode delamination, friction, and three-dimensional composite constitutive behavior remain future capabilities.
