Workflow and operator philosophy

Kyuubiki is moving beyond isolated single operators. The workflow direction is shader-like and neural-network-like composition: operators connected through a stable cross-operator data contract.

Back to book Previous chapter Next chapter

Core workflow ideas

  • Workflow graph growth should be intentional, not ad hoc.
  • Dataset transport should be portable and contract-driven, with an ONNX-like spirit.
  • Operator library ownership remains centralized instead of replicated to every agent.

Why this matters

Once operators can compose reliably, the system can grow toward larger simulation authoring flows without losing headless repeatability or distributed execution discipline.

Rich descriptions, stable execution IR

Material frame tasks may describe rectangle, I-section, circular, hollow-box, T-section, or custom layered sections. The runtime validates and compiles every description into the same centered fiber representation before the Agent engine executes it. This keeps authoring convenient without coupling the solver to UI-specific section objects. 

{
  "kind": "layered",
  "layers": [
    {"y_min": -0.30, "y_max": -0.10, "width": 0.05, "fiber_count": 4},
    {"y_min": -0.10, "y_max": 0.15, "width": 0.02, "fiber_count": 5},
    {"y_min": 0.15, "y_max": 0.30, "width": 0.10, "fiber_count": 3}
  ]
}

Layers may touch or remain separated, but cannot overlap. Area, centroid, and second moment must agree with the parent frame element. Geometry alone does not infer a composite; material assignments use the explicit ID catalog shown below. 

{
  "kind": "polygon",
  "vertices": [
    {"y": -0.20, "z": 0.00}, {"y": -0.20, "z": 0.05},
    {"y": 0.10, "z": 0.05}, {"y": 0.10, "z": 0.20},
    {"y": 0.20, "z": 0.20}, {"y": 0.20, "z": 0.00}
  ],
  "fiber_count": 16
}

Polygon sections accept one simple finite ring, including concave profiles and either vertex orientation. Self-intersection, holes, multiple rings, and composite fiber materials are not silently inferred. 

{
  "section_library": {
    "kind": "layered",
    "layers": [
      {"y_min": -0.20, "y_max": 0.00, "width": 0.10, "fiber_count": 4, "material_id": "soft"},
      {"y_min": 0.00, "y_max": 0.20, "width": 0.10, "fiber_count": 4, "material_id": "stiff"}
    ]
  },
  "fiber_materials": [
    {
      "id": "soft",
      "youngs_modulus": 7.0e10,
      "yield_strength": 1.0e8,
      "hardening_ratio": 0.02,
      "damage": {
        "onset_equivalent_plastic_strain": 0.001,
        "failure_equivalent_plastic_strain": 0.02,
        "maximum_damage": 0.4
      }
    },
    {"id": "stiff", "youngs_modulus": 2.0e11, "yield_strength": 5.0e8, "hardening_ratio": 0.02}
  ],
  "residual_stress_template": {
    "kind": "self_equilibrated_quadratic",
    "peak_stress": 5.0e7
  }
}

Material IDs are resolved before execution and returned in result diagnostics. The optional quadratic residual-stress template is projected against constant and linear section modes, so its discrete axial force and bending moment vanish before the requested peak magnitude is applied. Explicit fiber stresses and templates are mutually exclusive, and every generated stress must remain inside its phase yield surface. Individual phases may also opt into bounded equivalent-plastic-strain damage. The nominal stress and consistent tangent degrade while damage remains monotonic and frozen during elastic unloading; results expose maximum damage and damaged fiber point count. The frame-fiber scope still assumes perfectly bonded uniaxial fibers. A separate solve.cohesive_interface_1d operator now evaluates bilinear opening, damaged unloading/reloading, complete tensile failure, and compressive closure as a composable history contract. A four-node solve.cohesive_interface_2d element kernel now projects upper/lower displacement jumps into local opening and shear, rotates tractions back to global coordinates, and emits exactly self-balanced nodal forces. Two-point Gauss integration retains independent history at each point and emits a complete 8 x 8 consistent material tangent. The separate solve.cohesive_interface_mesh_2d operator now resolves a material catalog and assembles multiple kernels into an incremental Newton equilibrium system. Loads and optional non-zero constrained displacements advance proportionally, so retained monotonic paths can cross peak traction and reach complete separation. Explicit control histories additionally support cyclic and non-proportional constrained paths with per-step traction, reaction, displacement, residual, and directional-damage summaries. Trial Gauss-point histories are committed only after convergence; failures retain the previous state and expose a reason. Optional two-node linear component connector springs now share the global DOF assembly with cohesive elements. A retained series closed form verifies common equilibrium, displacement decomposition, connector force, and strain energy through solver, Agent RPC, and workflow paths. Small-displacement linear 2D host trusses now reuse the public truss protocol and contribute physical EA/L stiffness to that same global system. A second retained series reference verifies truss strain, stress, axial force, energy density, and common equilibrium. This is the first real structural host element. Constant-strain plane-stress triangles now add the first continuum host through the public plane-element protocol; a prescribed-apex series reference verifies analytic stiffness partition, common force, continuum stress, and energy. Fully integrated plane quads and Euler-Bernoulli frame hosts now use the same sparse Newton assembly. A separate solve.cohesive_interface_mesh_3d operator provides a true six-node triangular surface with two tangential and one normal history at each of three integration points. Optional tetrahedral solids reuse the native solve.solid_tetra_3d element kernel and share the same global DOFs, residual, and tangent. Retained references cover uniform opening, unloading damage, rigid coordinate rotation, interface/solid equilibrium, Agent RPC, Engine Workflow, headless HTTP submission, and a 1,440-DOF sparse model. Shell hosts, higher-order faces, coupled mixed-mode laws, and scalable sparse-indefinite factorization remain open. Post-peak continuation, coupled mixed-mode delamination, friction, three-dimensional composite constitutive behavior, and arc-length continuation remain future capabilities.

Input bindings before execution and recovery

Both the Rust graph executor and Orchestra validate connected input edges before executing any node. A second connection to a single-input node is a graph error, not another input that can be silently ignored. The same gate applies when Orchestra rebuilds a retained workflow.

  • solve, extract, export, condition, and ordinary single-payload transforms accept at most one incoming edge. Declared but unconnected spare ports are allowed. Missing inputs still use the existing execution and explicit failure policy.
  • Named multi-input transforms assemble a payload keyed by target port. Use an existing combination operator to construct a solver payload, then connect that one artifact to the solve node. A custom operator name does not itself declare a multi-input binding mode.
  • transform.first_available waits for all predecessors to resolve and chooses the first available artifact in edge declaration order. Consumed-artifact and lineage records name only that selected source, not unused alternatives.
  • Input nodes read input_artifacts and cannot have incoming edges. Output nodes may receive multiple ports; each port retains its own value and source lineage.
  • on_error: "skip", compact responses, retained solve artifacts, and retained branch decisions cannot bypass this graph gate. Synchronous and asynchronous API requests return a validation error before dispatch or job admission.
  • Native receipt reuse needs an unambiguous original attempt. If the same parent/task has a success plus another dispatched attempt, stop with dispatch_attempt_ambiguous rather than choosing by timestamp. Confirmed non-dispatched attempts are not competing results. After reading, recheck the selected journal record before the final claim/lease gate. Changed or evicted observations block with dispatch_observation_changed; journal loss and new unknown outcomes also block. No peer fallback or automatic rerun is authorized, and skip-on-error cannot publish a partial success. Read-only inspection of an explicitly selected historical attempt remains available.
  • Each dispatch attempt accepts only one observation after its initial unconfirmed state. Unknown is not upgradeable by a late completion. Identical repeats verify the original disk record without rewriting timestamps or refreshing retention; conflicting or malformed updates reject only the request. Real storage loss still blocks dispatch. Explicit receipt retrieval remains read-only and cannot erase uncertainty. These checks do not authenticate an observation or create an atomic transaction spanning Agent, dispatch journal and job publication.
  • Cached dispatch history is checked against disk before lookup or replay admission. Verify directory membership even for empty queries, then check the selected records, including relevant terminal and legacy observations. Changed, missing or partial evidence blocks rather than authorizing stale reuse or sending inspection/cancellation RPCs. Native receipt reuse repeats this check after retrieval. The shared public receipt API also requires its exact observation to survive lookup; concurrent transitions or eviction reject that read without poisoning healthy history, while storage damage still fails closed. Reads do not write or renew retention; these are live integrity checks, not a full scan of every payload or proof of history lost before process startup.
  • Coordinator-managed native workflows additionally persist a compact attempt identity in their private recovery record before sending the RPC. The exact attempt must survive in the journal at recovery admission and runtime reuse; an absent directory or another same-task attempt is not evidence of never having executed. Failed evidence commits send no RPC; unknown completion remains recovery-blocked, including skip-on-error. The 512-entry/512-KiB bucket stores no task payload or result and is pruned on ordinary terminal states. Missing legacy native evidence blocks rather than being silently reconstructed. This source-tested fence depends on the recovery record surviving; it is not cross-store atomicity, installed qualification or protection from joint store rollback.
  • Dispatch history now protects active or recovery-blocked parents and inconsistent recovery state. Matching ordinary terminal parents release protection once the private envelope and attempt bucket are pruned. Unprotected terminal history uses the 128-record window; protected and unresolved attempts still count toward the unchanged 512-record hard cap. Parent metadata lookup stays outside the journal process; failure stops new admission without deleting evidence or poisoning healthy reads. Local SQLite and memory tests cover retention/restart, not longer Agent receipt lifetime or exactly-once execution.
  • Managed native diagnostic/scoring successes now hand off their verified receipts into a bounded private checkpoint before downstream publication. Later claims can continue with the Agent offline, while still requiring unique original success history, the exact observation digest, matching TaskIR/attempt and claim/lease checks. The separate per-parent budget is 32 entries, 512 KiB per receipt and 2 MiB total; full/oversize results do not evict old evidence or authorize replay. Missing handoff requires the original Agent receipt. Failed commits/corruption block even with skip-on-error; ordinary terminal states prune the bucket. Controlled-TCP application-restart tests are not new live Rust Agent, installed or power-loss qualification.
  • Managed native workflows now propagate a sealed unknown dispatch outcome immediately as recovery-blocked, retaining their original attempt evidence. Disconnects, invalid receipts and local progress errors cannot be skipped or automatically sent to a peer, even with idempotent/checkpoint hints. Concurrent cancellation cannot hide the uncertainty. Pre-execution connection/capacity rejection still permits failover; local callbacks do not penalize Agent health. Standalone TaskIR and raw solver replay policies are unchanged. These are controlled-TCP source tests, not new installed or physical-Agent qualification.
  • Ordinary coordinator failure now verifies native dispatch evidence before cleanup. The workflow runner deadline cannot discard an in-flight attempt merely because its local transport was killed: unresolved or damaged evidence retains blocked recovery. It now commits actual targets with failure before shutdown and cancellation, without treating the acknowledgement as execution completion. Confirmed failures still clean up normally. Local controlled-TCP regressions cover this path. Periodic watchdog decisions now use the same owning coordinator, require the original scanned job, and atomically update job/recovery state before stopping the local runner. Stale decisions and rejected commits leave live work intact; unrelated work on the same Agent continues. Automatic cleanup now captures original RPC IDs and cancels only matching observed process/generation targets on original configured endpoint sessions, without job-wide fallback. Even later same-job requests are excluded. Periodic watchdog and runner deadline retirement retain a bounded, sealed intent atomically with failure. It persists attempts and the exact observed target before sending; startup/explicit recovery can retry that target at most three times without selecting a new generation. Exhaustion remains unresolved, not proof of termination. A bounded sweep is not a retry daemon; work left while it is busy needs another sweep. Runner deadlines recheck the active claim before commit, retain the waiter on selected transient write failures and never turn late output into parent success. Authority loss still fences local work; stale runners cannot cancel a newer execution. Ordinary-failure cancellation and explicit user cancellation are not upgraded. No automatic historical repair or physical Agent shutdown qualification is claimed. See the watchdog intent contract and runner deadline extension.
  • Ordinary failures and native/solve/branch checkpoint blocks now wait through selected terminal-write failures rather than silently exiting into runner-loss recovery. The original reason and registered runner remain; only the fenced persistence operation retries, not the computation. New claims, competing terminal decisions and lost authority stop the old finalizer. Rejected solve checkpoints cannot publish successful output. This is not a durable uncommitted failure log or parallel-branch recovery. Runner/process loss and watchdog policy still use existing recovery rules. See the failure persistence report.
  • After the whole graph succeeds, final publication now uses the same fenced terminal-write wait. Selected transient failures retain the original shaped output without calling the solver again. New claims, terminal decisions, deletion and lease loss prevent late publication. Known encoding/schema failures are non-retryable and do not expose result contents in their message. This does not turn a rejected intermediate checkpoint into success or change watchdog policy. See the final publication report.
  • A follow-up stages the final shaped result durably before publication. After process loss, an identity/digest/claim-checked handoff starts only a finalizer, not the graph, and does not increment execution attempts. Corrupt or stale handoffs cannot fall back to recomputation. The private record is bounded (64 MiB result, 2,000,000 JSON nodes, depth/string limits) and pruned on ordinary terminal transitions; unsupported output rejects without a false durability claim. SQLite WAL/FULL and actual child-BEAM SIGKILL/restart tests cover the pending-publication boundary on SQLite and JSON. This is not physical power-loss, hardware-cache or live PostgreSQL qualification. See the durable publication report.
  • Orchestra also binds recoverable solves, condition decisions and native receipts to the actual consumed path through rebuilt local nodes. A join selecting another source must not reuse an old result merely because its final input value is equal. First-available joins bind only the selected source; unused alternatives do not invalidate the same path. One recursive short digest per published artifact is ephemeral, not a retained ancestor tree or a copy of the payload.
  • The native diagnostic/scoring adapter also binds lossless input, configuration and context JSON to task identity. TaskIR v1 alone rounds small floats for digesting; changed tiny values must not authorize an old receipt. The adapter replaces supplied bindings without changing original numbers or routing authority. This is not a general TaskIR precision upgrade or an independently verified Agent-side binding.
  • TaskIR also supports an explicit typed IEEE-754 v2 digest encoding. Rust and Elixir authors retain decoded binary64 values and bounded integers; the control plane, Rust SDK and Agent independently recompute identity. Shared numeric vectors and real HTTP/Agent tests cover five diagnostic domains. Unknown encoding and tiny changes fail before execution. Typed tasks require an explicit Agent encoding capability and RPC method; old or unprofiled peers are not fallbacks. Ten HTTP-dispatched Rust/Elixir tasks retain original receipts across an Orchestra restart without re-execution. Agent restart instead returns unknown outcomes, without replay or publication. Builders still default to legacy pending installed-peer and default-adoption acceptance. Explicit defaults.native_task_digest_encoding now selects the native diagnostic/scoring adapter; new-codec workflows retain one lossless execution JSON string. Five source solved-domain chains restore solve outputs, branch decisions and native receipts across real Orchestra restarts without repeated completed work or changed scoring identity. Lost Agent receipts block continuation when no valid private native handoff is available. A PostgreSQL follow-up repeats seven bounded source macOS rounds against a remote JSONB store and checks rollback, selected-pool lease fencing and numeric identity. This is not Linux Agent, installed-runtime or default cold-start acceptance. Solve RPCs and local transforms do not change encoding; old evidence is never silently resealed. This is not arbitrary-precision decimal identity or authenticated author provenance.

Input binding does not add snapshot history or make local transforms durable. Recovery still rebuilds local transforms and joins, checks exact checkpoint invocations, and blocks ambiguous native outcomes. Operator availability remains specific to each runtime's catalog. Previously unbound recovery records cannot be silently adopted by a bound invocation; submit a new job explicitly rather than deleting evidence to authorize replay. These path digests do not authenticate data provenance or establish numerical correctness.

Summary cross-check gates

Connect reference and candidate summary objects to the left and right inputs of transform.validate_summary_tolerance. Its kyuubiki.summary_tolerance_validation/v1 report can feed transform.compose_quality_objective or the Rust Headless SDK material quality gate. A completed node is not itself proof of a passed comparison or a physically converged solution. 

{
  "fields": ["peak_temperature_c"],
  "absolute_tolerance": 0.05,
  "relative_tolerance": 0.001,
  "fail_on_missing": true
}
  • The example is node configuration. Tolerances must be finite and nonnegative; zero is valid. A field passes if either its absolute or relative error is within tolerance. Omitted tolerances default to 1e-9 absolute and 1e-6 relative.
  • An explicit field list must be nonempty, with unique nonblank strings. Without it, numeric keys from either summary are selected in sorted order. One-sided numeric fields and numeric/type changes are recorded as missing evidence, not silently excluded.
  • At least one field must actually be compared before the report can pass. fail_on_missing: false allows partial evidence, not an empty comparison. Missing fields block by default.
  • Present null or wrongly typed options are configuration errors; they do not fall back to defaults. An omitted or null whole config uses defaults. An unrepresentable error fails with the field name, rather than producing a null error metric.
  • Quality consumers require an explicit pass, a positive checked count, zero failures, and missing counts consistent with the missing-field policy. Nonempty or malformed failure details also block. Invalid success metadata remains available for repair planning.
  • Invalid configuration and non-finite errors fail the workflow by default. With an explicit on_error: "skip" recovery policy, the failed node retains its diagnostic, dependent work is skipped, and independent branches may finish. That is recovery, not successful validation.

This gate checks summary agreement, not independent scientific correctness. Model assumptions, convergence, reference quality, and physical validation still need their own evidence.

Quality ranking and incomplete evaluations

Quality scores are nonnegative penalties, not arbitrary signed physical quantities. transform.compose_quality_objective rejects non-finite arithmetic, negative scores, malformed configured numbers, and overflowing aggregate counters with the affected source and field. Valid zero weights and large finite values remain supported. Explicit blocking terms override a source's claimed ready flag.

Use an explicit qualities object when a candidate also carries metadata. Every named quality summary must be an object; missing or malformed sources cannot silently disappear. Candidate IDs must remain unique, including automatically assigned array IDs.

  • transform.rank_quality_candidates retains evaluable candidates in ranking. Each rejected evaluation is recorded in rejected_candidates with its candidate_id and error.
  • candidate_count counts ranked candidates; input_candidate_count includes rejected candidates. rejected_candidate_count counts the rejection records. ranking_complete is false if any evaluation was rejected. Completeness does not imply that every ranked candidate is ready.
  • If all evaluations are rejected, ranking fails with their count and the first named failure reason. It does not invent a winner.
  • transform.prepare_quality_next_round_request refuses missing, malformed, or negative selected scores instead of treating them as zero. Supplied completeness counters must agree with the ranking and rejection arrays.
  • Rankings must already be ordered by declared readiness (ready first), ascending score and exact candidate ID. A supplied rank must match its one-based array position. Admission rejects an incoherent order rather than silently changing the winner; matching best-candidate metadata does not override this check.
  • Each present objective.composite_quality_score must numerically equal its row's score. Every row's objective must also have valid types and no explicitly failed final convergence markers, not just the selected row. Missing objective/score fields remain permitted for shorthand contracts; they are not proof of physical correctness. This checks score copies, not a recomputation of objective terms.
  • Incomplete evaluation produces replan with a repair_rejected_candidates hint and retained rejection details. Even require_ready: false only permits an unready candidate to continue; it cannot satisfy the stop condition.
  • Coupled-readiness reports in the row, objective and payload are aliases: null cannot hide a supplied report, and non-null copies must be structurally equal. Conflicting or malformed reports reject, including malformed reports in lower-ranked candidates. A false readiness flag or blocking/missing domains requires repair; warning domains require review rather than successful completion. Repair hints and sweep case metadata retain this intent. Reconcile reports explicitly before a fresh run; the system does not merge them.
  • Direct quality-sweep requests validate aliases before stopped or incomplete branches. The request report, selected report, top-level report and request_payload.seed_objective.coupled_readiness must agree; duplicate hint objects must also agree. A blocked report requires replan and fix_coupled_readiness; warnings require a non-stopped action with review_coupled_readiness. Conflicting source, state, recommendation, domain-list or count mirrors reject. Reconcile the request explicitly rather than relying on field precedence.
  • Existing plans entering transform.materialize_quality_sweep_expansion must keep enablement, action, coupled evidence and repair hints consistent. Supplied repair_strategy and repair_focus mirrors must match their hint/report fields. Enabled stopped or incomplete plans reject; disabled repair diagnostics produce no cases. A missing action permits shorthand, but an explicitly contradictory action never gets replaced.
  • Direct transform.expand_parameter_sweep also checks supplied quality case_metadata before generating cases. The payload, embedded config and caller config cannot carry different metadata or use null to hide another quality alias. Readiness, repair hints, strategy/focus and incomplete markers use the same plan rules; disabled or budget-blocked metadata cannot authorize execution. Ordinary raw scans retain custom JSON metadata when no reserved quality fields are present. These checks do not authenticate evidence or independently verify physical validity.
  • Direct transform.compose_quality_execution_batch cannot bypass quality admission by supplying already expanded cases. Batch and candidate quality fields, metadata and case_metadata are checked independently before compiling any TaskIR. Preparation and execution recheck compiled batches before any task dispatch. A null metadata field does not erase evidence in another scope. Reserved readiness, convergence, completeness, repair and enablement fields follow the same plan rules. Explicit repair or review intent is allowed; disabled or budget-blocked evidence is not.
  • Quality evidence survives batch composition and participates in the batch digest, including top-level evidence. A changed admissible repair declaration requires a new preparation/checkpoint rather than reusing an old digest. Existing checkpoints whose batches used previously unhashed top-level evidence require explicit regeneration; there is no silent upgrade. Numerical TaskIR and Agent dispatch contracts are unchanged. Generic JSON metadata remains caller-owned, and ordinary per-task failures still isolate the failed case. This does not authenticate caller evidence or qualify general durable recovery.
  • Direct task batches require nonblank, unique case IDs and actual TaskIR IDs. Malformed task containers reject before any dispatch, including when the bad entry is last. Checkpoint creation and verification reuse this gate, validate supplied recovery targets against the batch and reject malformed or independently rewritten resume policies. Public batch routes return HTTP 422 rather than crashing or silently merging identities. Empty batches and optional header shorthand remain supported. These are structural consistency checks, not authenticated execution evidence.
  • Preparation reuse requires batch/phase-bound task identities, consistent integer counters and aligned failure reasons, not merely zero errors. Execution checkpoints retain compact completed-task identities rather than full result payloads. Completion flags and unresolved targets are recomputed and compared when reading the checkpoint. Missing evidence remains unresolved even when another task failed; foreign run evidence requires inspection, not direct retry. Legacy preparation/execution summaries without these records cannot authorize reuse. Explicitly regenerate from original records; do not silently recompute jobs or promote a saved completion flag. Checksums and compact evidence establish consistency, not signed provenance or independently authenticated computation.
  • Execution recovery checks failed/blocked task identities, inner and outer Agent failure receipts, and disjoint completed, failed, blocked and skipped partitions against exact counters. Checkpoints retain critical receipt fingerprints and compact blocked readiness, not full result copies. These records are rechecked on read; changing a recovery flag and rehashing the checkpoint cannot bypass a mismatch. retryable_case_ids lists explicit retry candidates; repair_required_case_ids lists verified nonretryable failures. continuation_blocked preserves unsafe-continuation advice and blocks unverified recovery, but false is not dispatch permission. automatic_replay_allowed is always false. Contradictory executions remain diagnostic with no recovery actions; their static recovery_evidence_error names the failed check, not its rejected value. Legacy execution summaries missing recovery evidence need explicit regeneration from original records. Neither a retry candidate nor a matching fingerprint authenticates the original attempt or grants ownership after restart.
  • An incomplete ranking or a nonempty rejected-candidate list disables downstream quality-sweep planning and expansion. The result contains zero cases, keeps sweep_action: replan, and exposes sweep_blocking_reason: candidate_evaluation_incomplete plus source_rejected_candidates. Repair those inputs and rerun ranking before generating another parameter sweep.

A disabled sweep awaiting repair is not a converged or completed study. These checks preserve numerical and workflow integrity; they do not replace independent physical validation.

Parameter sweep budget boundaries

Planning, materialization, and expansion share the same count rules. max_cases is a nonnegative whole count; zero allows no cases. samples_per_axis must be at least two and max_axes at least one. Exact floating representations such as 4.0 are accepted and emitted as integers. Null fields, strings, negative or fractional counts, and out-of-range counts are errors, not requests to use a larger default. Defaults apply only when a field is absent.

  • The planner validates every search-space axis, selects axes by focus and axis budget, then checks the Cartesian product with overflow detection before allocating range samples. Malformed or empty axes cannot silently shrink the search. Truncated axes remain visible in the budget's usable count and follow-up recommendation.
  • Over-budget plans are diagnostic-only. Their axes contain value_count and values_deferred: true, without a values array. This avoids generating large sample arrays that would immediately be rejected.
  • For an executable plan, materialization and expansion verify the actual axis product against the effective limit. Stale estimates and a claimed ready flag cannot authorize excess cases. Lowering the limit in either stage takes effect before case generation.
  • Materialization and direct expansion reject supplied totals and per-axis counts that disagree with the axis product. Deferred axes require a blocked upstream budget and positive whole counts; the product is checked for overflow without allocating samples. A stale declared count is an error, not a request to normalize the plan silently.
  • Direct expansion checks count mirrors in the envelope, body, quality metadata and their budgets before stopped or budget-blocked returns. Deferred axes cannot also contain values, even null or an empty array. Diagnostic-only envelopes may omit axes, but supplied counts must still agree. A budget cannot claim unblocked if its known count exceeds its own limit. Ordinary custom metadata without reserved quality fields remains separate from these plan-count rules.
  • A quality-sweep budget block returns zero cases with expansion_budget_ready: false and expansion_blocking_reason: case_budget_exceeded. Candidate identity, estimated count, and budget diagnostics remain available. Raising a downstream limit does not release an upstream block: adjust the planning inputs and build a new plan.
  • Direct transform.expand_parameter_sweep requests above their limit return an error. Invalid counts and arithmetic overflow also return errors rather than partial sweeps or wrapped counts. An explicit workflow recovery policy can preserve independent branches while retaining the failed-node diagnostic.

Billion-sample deferred-plan tests validate rejection without sample allocation; they do not demonstrate billion-case simulation capacity. Range interpolation preserves finite endpoints even when subtracting the two endpoints directly would overflow.

Parameter sweep target integrity

Active quality-sweep materialization and direct expansion validate labels and resolve every target against the base model before generating cases. Invalid targets return the axis index, full path, and reason. A generated case's parameters must describe the values actually assigned to its model.

  • Paths use nonempty dot-separated segments, for example nodes.2.load.1. Objects use literal field names, including numeric names. Arrays use bounded, nonnegative decimal indices; final array elements, nested arrays, and root arrays are writable. Negative indices, signs, append markers, and out-of-range indices are rejected.
  • All parent containers must already exist. A final object field may be inserted; missing parents are never created implicitly. An array assignment replaces an existing element without resizing the array. Dot characters within object field names are not escaped by this path syntax.
  • Labels default to the trimmed path only when absent. Supplied labels must be nonblank strings and unique across all axes, including implicit labels. Duplicate labels cannot merge parameter records or substitute another axis's value.
  • Targets must be disjoint. Duplicate targets and ancestor/descendant pairs such as material and material.density are rejected regardless of axis order. Decimal array aliases such as cells.0 and cells.00 resolve to the same target, while numeric object keys 0 and 00 remain distinct.
  • Paths are resolved once per expansion, not reparsed for every case. Iterative Cartesian enumeration preserves last-axis-fastest ordering, case IDs, labels, and metadata without recursive stack growth proportional to axis count.

Regression evidence includes 8192 single-valued axes, the quality planning/materialization/expansion chain, explicit branch recovery, and array-load cases passed to the cohesive mesh solver. The latter compare against manually constructed inputs and uniform elastic opening values. These bounded checks are not broad solver validation or large-scale simulation throughput measurements.

Sweep result identity and summary evidence

Joining execution results is an identity boundary, not a best-effort array merge. Every case must receive its own usable result before the batch can be summarized, scored, and used to plan another round. Malformed identities, configuration, and declared counts are errors.

  • Case and result IDs accept id, case_id, and caseId; supplied aliases must be nonblank strings and agree. Duplicate IDs are rejected. Cases without an ID receive case_<index>, checked for collisions with explicit IDs. Keyed results use one indexed lookup and never fall back to array position when a case's result is missing.
  • Positional matching is permitted only for an entirely unlabelled result batch with exactly one result per case. Mixing keyed and unlabelled results is an error. Positional mode cannot detect reordered results: distributed callers should supply stable case IDs. The output reports matching_mode.
  • A selected summary must be an object. Supplied statuses must be ok, success, succeeded, completed, complete, done, or joined; a non-null error rejects the result even with a successful status. Status-only envelopes are not summaries. Missing or rejected results cannot retain a previous run's summary or result alias.
  • With strict: false (the default), the join preserves diagnostics in missing_case_ids, rejected_results, and unmatched_result_ids, with their counts. Rejected results also count as missing usable summaries. Any missing, rejected, or unmatched result sets join_complete: false. Strict mode returns an error instead. Neither mode authorizes scoring an incomplete batch.
  • An explicit join summary_field selects only that result field, without silently trying other payloads. A custom output_field is recorded as joined_summary_field and inherited by the summarizer; an explicit summarizer selection must agree. Identity, model, parameters, metadata, and result-status fields cannot be used as join output fields.
  • Summary field selections must be nonempty, unique, nonblank strings, or are inferred from the union of summary keys. Metrics cannot replace the row's case_id, parameters, or metadata. Missing and null metrics fail by default. A field numeric in one case cannot silently become text in another and shrink the aggregate sample.
  • fail_on_missing: false permits diagnostic rows with summary_complete: false, missing_field_count, and missing_fields. Such rows are not scoreable. Finite signed numeric values and present text fields remain supported. Numeric accumulation checks count and sum overflow; non-finite intermediate sums return an error instead of JSON null or a reset accumulator.
  • Declared case, joined-summary, and row counts must match the actual batch. A claimed complete flag cannot override nonzero missing/rejected/unmatched evidence or contradictory counts. Explicit workflow recovery preserves failed-node diagnostics and independent branches, while dependent scoring and replanning nodes are skipped rather than given synthetic successful results.

Regression evidence covers 4096 reverse-ordered keyed results, retries, custom summary fields, malformed identities, overflow, diagnostic-only summaries, and the full join-to-replanning chain. These are bounded contract and recovery checks, not a throughput benchmark or independent physical validation of the solver.
