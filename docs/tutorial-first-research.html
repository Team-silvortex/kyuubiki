Tutorial 01 · Workbench GUI

Finish one small research loop

This route proves the basic Workbench chain: project -> model -> saved state -> job -> result -> reopen. Use a small 2D truss so product wiring, not mesh size, is the variable under test.

Surface: Workbench Suggested time: 15 minutes Risk: normal Output: persisted project + result
Tutorial center Automate the same loop Recovery guide

Before starting

  • Open Workbench through Hub or the installed Workbench shell.
  • Confirm the event bar has no unresolved runtime-start or project-storage failure.
  • Keep the case small: about six truss bays, one material, and one load case.
  • Do not continue from an unknown active project. Create a new one or deliberately select an existing one.
Step 1

Create the research container

  1. Open the History / Library rail section.
  2. Open the projects view and create a project named tutorial-truss-loop.
  3. Confirm that the new project is selected before leaving the section.

Checkpoint: the active project id and name are visible, and the project list contains exactly the project you intend to modify.

Step 2

Build a bounded model

  1. Open Workspace / Model and choose the 2D parametric truss generator.
  2. Use six bays, span 18, height 3.5, and a vertical load near -1500 in the active unit convention.
  3. Inspect the viewport before solving: supports, load direction, connectivity, and scale must be visually plausible.
  4. Save the model as tutorial-truss-v1 using Save As.

Checkpoint: the model belongs to tutorial-truss-loop, has a stable model id, and reappears in the project model list.

Step 3

Run and wait for evidence

  1. Open Research / Study and review the active study kind, material, loads, and boundary summary.
  2. Run the current study once. Do not click Run repeatedly while the job is queued or running.
  3. Follow the observable job state until it becomes completed or a terminal failure is reported.
  4. If it fails, keep the job id and event message before changing the model.

Checkpoint: one terminal job record exists, it is associated with the selected project and model, and the result count is greater than zero.

Step 4

Inspect, then prove persistence

  1. Open Results for the completed job and inspect deformation shape, extrema, units, and warnings.
  2. Record the project id, model id, job id, solver/operator version, and the primary result metric.
  3. Return to History / Library, leave the project, then reopen tutorial-truss-loop.
  4. Reopen tutorial-truss-v1 and its result without rebuilding the geometry.

A colorful result is not a validation claim. This tutorial proves product closure and persistence only; physical trust requires an accuracy baseline and an appropriate convergence or cross-validation route.
