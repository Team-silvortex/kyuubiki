A model proposes; measured evidence decides

Run a bounded synthetic material-selection experiment against installed Orchestra and Rust Agent services. A model chooses candidate designs and observes real computations. Deterministic checks, not model confidence, determine numerical acceptance. A second model reviews the retained evidence and limitations.

Problem and execution boundary

Select each layer's conductivity from 2, 10, 100 or 200 W/(m K). Maximize axial heat flux subject to tip expansion not exceeding 110 micrometres at a 20 K boundary temperature difference. Geometry, expansion coefficients, elasticity, restraints and perfect contact are fixed by the layered thermal reference.

Sol proposes typed parameter batches
  -> caller validates the whole batch and resource limits
  -> Rust Headless SDK -> Orchestra -> Rust Agent
  -> heat Q4 -> temperature bridge -> thermoelastic Q4
  -> manifest checks + result readback + analytical numerical gates
  -> Sol observes evidence and selects an evaluated feasible design
  -> caller verifies discrete optimality and additional cases
  -> Astra independently critiques the evidence

The only model tool is evaluate_designs. It accepts batches of 1 to 4 approved conductivity pairs and refinement levels 1, 2, 4 or 8. Unknown fields, out-of-grid values and malformed batches fail before dispatch. There is no arbitrary code execution, filesystem tool, shell, configurable provider origin or model-issued approval. This study-specific example is not a required universal CLI and does not extend the GUI's model gateway.

Separate temperature boundaries from strain reference

The follow-up example fixes conductivity at [100, 200] W/(m K) and exposes only evaluate_cases: eight named synthetic scenarios, batches of 1 to 4, and refinement levels 1, 2, 4 or 8. The model must select at least four different scenarios. The caller then completes a fixed 20-case minimum matrix; successful identical cases reuse retained evidence without resubmission.

cargo test --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference

# Same external credential-file variable and explicit paid-run approval:
KYUUBIKI_LIVE_RESEARCH=1 cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- tmp/model-reference-round-001
  • baseline: boundaries 40/20, strain reference 20.
  • reference_only: unchanged 40/20 boundaries, strain reference 30. Heat flux is unchanged, but the analytical tip displacement changes from +100 to -50 micrometres.
  • uniform_hot and uniform_cold: both boundaries at 30 or 10 with reference 20. Zero heat flux does not imply zero thermal strain, restraint stress or mechanical energy.
  • absolute_shift and uniform_shifted: shift all absolute temperatures and the reference together; mechanical results should remain invariant. This is a constant-property numerical invariance test.
  • reversed_gradient: boundaries 20/40, reference 20. Heat flux reverses, but tip expansion remains positive; a negative gradient is not the same experiment as uniform cooling.
  • zero: both boundaries and the reference at 20.

The caller checks hard-coded analytical tip displacement and heat-flux expectations, distinct execution identities, fixed x/y constraints, structural temperature deltas, free-DOF residuals and Q4 strain-energy quadrature. Support resultants and equilibrium are independently reconstructed from returned displacement using rectangular Q4 quadrature and the analytical temperature field. They are not solver-returned reactions. Discrete Q4 energy is distinguished from continuum energy; their difference is not automatically a solver defect.

The same 16-request, 40-job and estimated USD 8 ceilings apply. This follow-up has at most 32 distinct approved scenario/mesh combinations rather than the design-selection example's 24 exploration evaluations. It remains a Poisson-ratio-zero, perfectly bonded, rectangular, linear-elastic reference study, not qualification of general geometry, pointwise stress peaks or material safety.

Break the material symmetry

Append coupling to the reference example to select eight material scenarios at all four mesh levels, for exactly 32 distinct approved cases. The existing reference suite is still the default. Scenario names from the other suite and arbitrary material fields are rejected before dispatch.

KYUUBIKI_LIVE_RESEARCH=1 cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- tmp/model-coupling-round-001 coupling
  • control: expansion [10e-6, 20e-6]/K, Poisson ratios [0, 0].
  • poisson_only: original expansion, Poisson ratios [0.3, 0.3].
  • ratio_only: expansion [10e-6, 35e-6]/K, Poisson ratios [0, 0].
  • coupled: expansion [10e-6, 35e-6]/K, Poisson ratios [0.2, 0.4].
  • coupled_hot and coupled_cold: the coupled material with uniform temperatures 10 K above or below the fixed strain reference.
  • coupled_auxetic: expansion [18e-6, 6e-6]/K and Poisson ratios [-0.2, 0.3], deliberately changing which layer has the larger curvature.
  • coupled_high_nu: expansion [10e-6, 35e-6]/K, Poisson ratios [0.49, 0.25]. Plane-stress acceptance is not a 3D incompressibility test.

Geometry, conductivities, Young moduli and constraints remain fixed. Except for the uniform cases, boundary temperatures are 40/20 with strain reference 20. Material expansion and Poisson ratios are included in execution identities, actual workflow input, retained evidence and the model's observations.

For this particular transversely restrained plane-stress reference, the continuum conditions give strain_x = (1 + nu) * alpha * theta, stress_x = 0 and stress_y = -E * alpha * theta, where theta is the departure from strain reference. These are derived reference relations, not rules for a transversely free body. The constitutive starting point is the plane-stress Hooke law. Adding thermal eigenstrain and applying the declared constraints gives the relations above.

Q4 midpoint errors are checked separately in each layer. If m and v are an element's mean and variance of theta, expected discrete energy density is E * alpha^2 / 2 * (m^2 + 2 * v / (1 - nu)), whereas continuum energy density averaged over the element is E * alpha^2 / 2 * (m^2 + v). Checks independently reconstruct the plane-stress constitutive response and equilibrium, and report force and moment residuals in separate units. A model cannot relax these gates or change the budget.

This suite does not validate arbitrary shear, free transverse deformation, distorted meshes, nonmatching field transfer or stress peaks. Numerical correctness and the inherited expansion-limit classification are separate; the latter is not an optimization target or material-safety assessment in this suite.

Release transverse restraints and exercise shear

Append planar instead of coupling to run eight affine plane-stress patches at four mesh levels. This is a homogeneous 1 x 0.25 m rectangle with thickness 0.01 m, E = 70 GPa, expansion coefficient 12e-6/K and conductivity 20 W/(m K). Exactly three rigid-mode restraints are used: origin ux/uy and bottom-right uy. Other transverse degrees of freedom remain free.

KYUUBIKI_LIVE_RESEARCH=1 cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- tmp/model-planar-round-001 planar
  • free_hot / free_cold: uniform +10/-10 K relative to reference, no mechanical loads, nu = 0.3 and zero analytical stress.
  • tension / tension_distorted: constant axial stress 1 MPa, nu = 0.3, zero temperature rise; tests include Poisson contraction.
  • shear / shear_distorted: constant shear stress 0.5 MPa, nu = 0.3, zero temperature rise; checks engineering shear convention.
  • mixed_hot / mixed_auxetic: stresses [1.2, -0.4, 0.3] MPa with nu/temperature rise [0.49, +10] and [-0.2, -10].

Boundary nodal loads represent t = sigma n on every exterior edge, not a cantilever load. Distorted cases perturb interior nodes while preserving the rectangular boundary. Free hot/cold and mixed cases also use distorted meshes. Uniform boundary temperatures leave interior temperature degrees of freedom to be solved. A refinement r uses (2r + 1)^2 nodes and (2r)^2 Q4 elements.

ex = (sx - nu sy)/E + alpha theta
ey = (sy - nu sx)/E + alpha theta
gamma_xy = 2(1 + nu) tau/E
ux = ex x + gamma_xy y; uy = ey y
energy density = [sx(ex - alpha theta) + sy(ey - alpha theta) + tau gamma_xy]/2

The caller checks every returned displacement and stress, principal stresses, von Mises stress, engineering shear and energy. Separate general Q4 Jacobian/quadrature reconstruction checks all-DOF force balance and strain energy without importing production solver routines. Returned stress/invariant fields include observed minima/maxima, expected values and errors, not just a combined pass flag. Final traction-displacement pairing f^T u is reported separately from its thermal and thermal-subtracted elastic parts. Only half the elastic part is compared with strain energy; none is called path-integrated work. Endpoint and energy references are also hard-coded independently of the model builder.

This tests affine displacement/constant stress on regular and irregular meshes, a limited use of the finite-element patch test. It is not a non-affine convergence test, a heterogeneous free-expansion study, nearly incompressible 3D qualification or general peak-stress validation. Forces are independently reconstructed, not solver-returned reactions.

Successful evaluations explicitly distinguish new execution from reused evidence. The independent reviewer receives a compact request/observation audit with real job IDs, not raw reasoning or credentials. Identical integer/float JSON encodings are accepted for material/load numbers; missing fields, changed values and non-boolean restraint flags are not.

To diagnose a failed check without paid calls or new solves, explicitly point the offline replay test at an owned directory whose raw result payloads have not yet been cleaned up. It validates the cases found and requires at least one result; it does not certify that all 32 are present.

KYUUBIKI_PLANAR_REPLAY_DIR="$PWD/tmp/model-planar-round-001" \
  cargo test --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference planar_replay_retained_results -- --ignored --nocapture

Nonuniform temperature, material jumps and bending

Append bending to select six scenarios at four mesh levels, for 24 distinct approved cases. This suite deliberately goes beyond affine patches: displacement is piecewise quadratic and Q4 results must converge toward the analytical continuum solution, not reproduce it exactly at every mesh.

KYUUBIKI_LIVE_RESEARCH=1 cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- tmp/model-bending-round-001 bending

Geometry is 1 x 0.25 m with thickness 0.01 m. Materials are layered through y, not x. Heat uses bottom/top temperatures with insulated vertical sides. Exactly three mechanical rigid-mode restraints are retained. Refinement r uses 4r x 2r rectangular cells, up to 561 nodes and 512 Q4 elements at r = 8. Free heat nodes start at the reference temperature, not the analytical solution; only prescribed bottom/top nodes receive boundary temperatures.

  • gradient_free: homogeneous E = 70 GPa, nu = 0.3, alpha = 12e-6/K, k = 20 W/(m K); bottom/top 20/40, reference 20, zero mechanical loads. gradient_free_reverse uses 20/0.
  • bilayer_gradient: equal bottom/top layers with E = [70, 20] GPa, nu = [0.2, 0.35], alpha = [10e-6, 30e-6]/K, k = [10, 40] W/(m K), bottom/top 20/40 and reference 20.
  • bilayer_gradient_reverse reverses the thermal increment using bottom/top 20/0. bilayer_uniform uses 30/30.
  • bilayer_shift shifts bottom/top/reference together to 293.15/313.15/293.15 without changing thermal strain or heat flux.

Boundary-condition distinction: homogeneous cases have no mechanical loads. Bilayer cases apply the analytical, self-equilibrated end traction sigma_x(y) n_x at both vertical ends. Zero net section force and moment do not mean zero local traction. These are not fully traction-free bilayer strips, clamped cantilevers or generic bimetal-strip certifications.

A separate opt-in control runs the free-gradient, bilayer-gradient, uniform-bilayer and shifted-bilayer cases at r = 8 without any model API calls or API key. It submits four real workflows to the local Orchestra/Agents and requires a new output directory. This is not a repeat of the complete 24-case matrix.

KYUUBIKI_LIVE_RESEARCH=1 KYUUBIKI_BENDING_PROBE_DIR="$PWD/tmp/bending-probe-001" \
  cargo test --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference bending_live_unseeded_temperature_probe -- --ignored --nocapture

The independent reference obtains temperature from series thermal resistances, and solves a 2 x 2 section force/moment balance for axial strain e0 + kappa y. It then integrates transverse strain and constructs a continuous piecewise-quadratic displacement field satisfying plane-stress equilibrium and the declared tractions. The constitutive starting point is the plane-stress linear elasticity law; the full boundary/reference derivation is in the linked run report.

The checker separately validates exact temperature/bridge properties, heat flux, returned stress/strain/energy postprocessing, all-DOF force residuals and an energy-error identity using independent rectangular Q4 quadrature. Elastic energy obeys 2U = f^T u - integral(sigma : thermal_strain); the traction-displacement pairing is not path-integrated work.

The caller requires relative nodal RMS error and the normalized quadratic strain-error energy to decrease by at least 20% per mesh doubling. At the finest level, nodal RMS and middle-bottom bow errors must be at most 2%, normalized error energy at most 0.001 and normalized stress L2 error at most 0.1. These are predeclared catalog acceptance limits, not universal finite-element error bounds. Nodal RMS is normalized by the analytical nodal displacement norm, stress by the characteristic E_max alpha_max |theta|_max, and energy by that stress squared times volume divided by E_min. Energy error is not divided by continuum elastic energy, which vanishes in the homogeneous free cases.

Diagnose bilayer energy error before changing the solver

The bending-energy suite revisits the 4.919177% elastic-energy error at 32 x 16. It uses four scenarios at refinements 1, 2, 4, for twelve actual workflows: gradient isotropic, x-only, y-only and uniform temperature isotropic. Geometry, materials and analytical end tractions remain those of the bilayer bending reference, not a fully traction-free strip.

KYUUBIKI_LIVE_RESEARCH=1 cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- tmp/model-energy-round-001 bending-energy

Gradient/uniform isotropic meshes are 16r x 8r, x probes are 16r x 16 and y probes are 32 x 8r. The finest mesh has 2,145 nodes. A separate banded-Cholesky Q4 implementation checks the production discrete solution without importing solver kernels. The comparison uses the same discretization and does not prove continuum accuracy. Both isotropic sequences must reduce ordinary relative energy error by at least 20% per step and finish within 2%; directional probes have no final accuracy gate.

Observed gradient errors are 19.3374%, 4.9192%, 1.2354% under isotropic refinement. X-only refinement finishes at 1.4679%, versus 4.6844% for y-only refinement. The baseline shear term is 93.6% of strain-error energy, not of the elastic-energy excess. Production/direct energy differences stay below 4.46e-11 J. These results support a case-specific interpolation limitation, not an iteration-tolerance failure or universal shear-locking diagnosis.

Large seed meshes must use the bridge's independent seed_model input alongside heat_result, leaving only the transfer contract in configuration. The shared research builder uses this form. Install an updated bridge runtime first: legacy runtimes reject this graph, and embedding a fine mesh in configuration exceeds its unchanged safety budget. Legacy single-input small graphs remain supported.

The offline interpolation audit rechecks all twelve retained jobs and their file hashes, compares the exact-displacement Q4 interpolant with the equilibrated result, and checks the Galerkin energy decomposition. Compare element order without changing production Q4

The bounded Q9 prototype solves quadratic steady heat, transfers all nine nodal temperatures on the matching mesh, then solves plane-stress thermoelasticity with full 3 x 3 integration and consistent quadratic end loads. It is a local research reference, not an installed Agent operator or a solver added to the headless SDK API.

cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example model_driven_thermal_reference -- \
  --offline-bending-order tmp/bending-order-round-001

Use a new output directory. This mode needs neither a model credential nor a running runtime, makes no model or network requests, and retains compact evidence rather than full fields. It compares four independent Q4 solves with equal-cell and equal-mechanical-DOF Q9 solves, plus four controls. Q4 uses the exact reference temperature field; Q9 solves temperature explicitly.

For the gradient bilayer, Q4 32 x 16 retains 4.919177% energy error. Q9 16 x 8 has the same 1,119 free mechanical DOFs and an absolute energy error of 1.0991e-13 J. The piecewise-quadratic solution is representable on this interface-aligned rectangular Q9 mesh; this result does not qualify arbitrary distorted meshes or fully traction-free bilayers.

The order comparison report records the finite-element definition, residual gates, negative controls and remaining production integration work. Existing Q4 acceptance limits, installed runtime and model-review results are unchanged.

Native Q9 solver package: bounded, partial validation

solve.thermal_plane_q9_rect_2d is now an optional Rust operator package, separate from the independent research reference above. Element mathematics live in the solver crate; the generic Agent loads the package through TaskIR and the existing JSON C ABI. No Q9-specific engine dispatch was added.

Input requires a conforming, single edge-connected mesh of axis-aligned rectangles, nine row-major nodes per cell, linear isotropic plane stress and an explicit temperature difference at every node. Limits are 4,096 nodes and 512 elements. The solver rejects hanging edges, overlapping/disconnected cells, insufficient restraints, unknown input fields and nonrepresentable values. This package does not contain a Q9 heat solver or automatically interpolate an arbitrary Q4 mesh. Its explicit matching-node bridge is described below.

cargo test --locked --manifest-path workers/rust/Cargo.toml \
  -p kyuubiki-solver --test thermal_q9_operator --test thermal_q9_bilayer
cargo build --locked --manifest-path workers/rust/Cargo.toml \
  -p kyuubiki-operator-thermal-q9
cargo test --locked --manifest-path workers/rust/Cargo.toml \
  -p kyuubiki-cli --test operator_q9_live -- --ignored --nocapture

The last command uses an isolated loopback Agent and a temporary package root, verifies execution, rejects malformed geometry and a wrong library digest, then executes a valid task again. It does not replace installed services. Use the source-built Agent: an already installed 3.7.8 runtime does not acquire these changes merely because its version number matches. The native bilayer tests use analytical nodal temperatures and end tractions; at 16 x 8 cells the gradient energy error is 3.9097e-11 J with 59 sparse iterations. This is polynomial reproduction for this benchmark, not arbitrary-mesh certification.

The package manifest deliberately remains partial. Native solver cancellation is tested, but cancellation/progress context is not yet propagated across the dynamic-library ABI. No hard execution-time bound or process isolation is claimed for the in-process package. Durable workflow recovery, general multi-material interface qualification and cross-platform package runs remain open.

See the native package report, input schema and output schema. These checks made no new model API requests and did not reinstall the GUI or runtime.

Matching-node heat-to-Q9 chain

workflow_bridge.heat_to_thermal_q9_rect_2d lives in the same optional package, not in a new engine-specific dispatch branch. First solve solve_heat_plane_quad_2d on four Q4 cells per mechanical Q9 cell: both meshes use the same nodes, including every midside and centre node. Then pass the actual heat result and mechanical seed model to the bridge.

{
  "payload": {
    "schema_version": "kyuubiki.heat-to-thermal-q9-nodal/v1",
    "temperature_unit": "kelvin",
    "reference_temperature": 293.15,
    "heat_result": "REPLACE with the complete native heat result object",
    "seed_model": "REPLACE with a thermal-plane-q9-rect/v1 model object"
  },
  "config": {}
}

The strings above are explanatory placeholders, not accepted payload values. The bridge output summary is the complete Q9 model; pass it unchanged as the solver's payload. Only temperature_delta is replaced by solved Kelvin minus the explicit reference. Loads, restraints, material properties and topology remain unchanged.

  • Node IDs must be unique and coordinates must match exactly. Result arrays may be reordered, but their indices must identify the correct source input nodes.
  • Each Q9 cell must correspond to four unique, oriented Q4 subcells of the same thickness. Changing only array lengths is insufficient; connectivity is checked.
  • Missing temperatures, unknown units, invalid geometry/materials, duplicate identities, thermal contact interfaces and unknown bridge controls are rejected. There is no nearest-neighbour fallback, guessed reference or temperature scaling.
  • The contract checks correspondence, not authenticity or physical correctness of an arbitrary supplied result. Keep execution receipts with research evidence.

The isolated Agent suite now executes eight actual heat → bridge → mechanics chains, including nonzero Poisson ratios, reversed temperature gradients and conductivity ratios up to 100. The 16 x 8 gradient case uses 561 shared nodes and has absolute energy error 6.38814e-11 J against an independent section solution. Boundary tractions are prescribed from that solution; this is not a fully traction-free bilayer benchmark.

This is client-sequenced RPC/TaskIR execution, not an atomic or resumable workflow graph. Wrong-unit and stale-identity bridge calls fail before a mechanical submission; valid work then succeeds on the same Agent. See the heat-chain evidence and portable bridge schema. Matching nodes do not upgrade Q4 heat accuracy to Q9 heat accuracy.

Cost, credentials and failure handling

  • Models: gpt-6.1-sol for planning/tool calls and gpt-6-astra for independent review, both using Responses API, high reasoning effort and the default service tier. No silent model fallback.
  • Per run: at most 16 API requests, 10 planning turns, 24 exploration evaluations in the design-selection example (up to 32 distinct cases in the follow-up suites), 40 actual workflow submissions, 128 KiB serialized input per API call and 8,192 output tokens per call. A cached successful evaluation does not resubmit work.
  • An estimated USD 8 ceiling is enforced by reserving an upper estimate before each request. Pricing is pinned to the verified 2026-11-04 standard rates: Sol USD 2/10 and Astra USD 10/50 per million input/output tokens. Cached-input discounts are not subtracted. Recheck rates before future runs.
  • This is not an account-wide billing limit. Separate runs and other clients consume additional credits. Usage is recorded from API responses; the estimate is not a provider invoice or a query of remaining credit.
  • The key is read into process memory and sent only in the authorization header to https://api.openai.com/v1/responses. Redirects and proxies are disabled. Requests set store: false; provider-side policies still apply. Only this synthetic problem and evidence are sent.
  • Transport errors, ambiguous workflow outcomes, incomplete model responses and failed gates stop the run without automatic retry. An API timeout retains its reservation as unknown cost. A workflow timeout does not guarantee cancellation.

Reservations, requests, terminal records, results, checks and usage are immutable create-new files, flushed before proceeding. This is not a transactional research database or a power-loss recovery guarantee. There is no automatic resume; reconcile uncertain work and costs before authorizing a new run. Do not delete pending evidence merely to bypass a failed run. Raw reasoning envelopes are kept in memory for stateless continuation, not written into reports.

What passing means

Each real workflow must complete, satisfy the output manifest, and return an identical result on a second fetch. Nodal temperatures, reference subtraction, axial displacements, transverse constraints and fluxes are checked against the analytical layered solution. Corrupted temperature, displacement, reference and geometry evidence must fail validation.

The selected pair is checked against an exhaustive 16-pair analytical oracle, then at four mesh levels and with temperature-origin shift, zero rise, doubled rise and negative rise. Additional cases at 21.999, 22 and 22.001 K bracket the selected pair's tip-displacement limit. Fractional load values remain distinct in case and workflow identities; display rounding must not merge evidence or trigger cache reuse. The oracle is not presented as 16 actual SDK solves. Doubling the load is a verification case and can violate the original design limit without indicating a solver failure.

The feasibility classifier uses the largest tip displacement and a predeclared 1e-9 m numerical band. Values within that band of the 110 micrometre limit are boundary, not approved feasible. The band reflects the existing displacement-check tolerance, not uncertainty in real material properties. Negative displacement is judged against the stated one-sided expansion constraint; passing it does not qualify contraction, stress or bond strength.

Additional checks report interpolated element-centre displacement error separately from nodal error, compare it with the expected quadratic-reference interpolation error, validate element-mean axial strain and restraint stresses, and integrate boundary flux into heat rates. These are not general pointwise stress, stiffness, solver-reported reaction-force or arbitrary-geometry qualifications. Mechanical scope depends on the selected suite: layered cases use their declared rectangular reference and material properties; planar cases use homogeneous affine patches. Neither establishes general nonlinear or peak-stress accuracy.

Inspect numerical-report.json, independent-model-review.json and report.json separately. A model review cannot override a failed numerical gate. Review issues yield a nonzero exit even when the numerical report passed. Missing final reports mean incomplete evidence, not success. The result remains a synthetic verification example, not material certification, uncertainty qualification or an industrial safety assessment.
