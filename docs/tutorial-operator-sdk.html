Tutorial 05 · Rust Operator SDK

Add executable operator capability

The Worker/Operator SDK is Rust-only and extends what an agent engine can execute. It is separate from PWDT frontend automation and from the Rust, Python, or Elixir Headless control SDKs.

Language: Rust Output: typed operator package Gate: readiness + baseline + preflight
Tutorial center Operator SDK reference Reliability policy

Step 1

Run the untouched template

cd workers/rust/templates/operator-crate-template
cargo test
cargo run

Checkpoint: the descriptor-readiness test passes and the sample prints a JSON summary for the small temperature collection.

Step 2

Create an external-local package

  1. Duplicate the template into a new crate under your local operator package root.
  2. Rename the crate, package id, operator id, family, and entry symbol.
  3. Replace the sample input/output types with explicit typed contracts.
  4. Update kyuubiki-operator.json so SDK compatibility, host version, validation status, notes, and operator ids match the implementation.

Keep validation_status at partial until repeatable baselines, tolerances, and documented limits exist. “It ran once” is not verified.

Step 3

Make the descriptor executable and reviewable

  • Declare stable input/output ports and schemas.
  • Declare domain, capabilities, runtime requirements, units, and determinism posture.
  • Return structured failures; do not collapse invalid input, numerical failure, cancellation, and infrastructure loss into one string.
  • Add a tiny golden case, a malformed-input case, and at least one tolerance-based baseline.
  • Keep operator implementation independent of Elixir task-description code. The runtime consumes protocol/TaskIR contracts.
Step 4

Preflight the package root

./scripts/kyuubiki operator-package-preflight ./operator-packages \
  --out tmp/operator-package-preflight.json \
  --fail-on-rejected \
  --fail-on-readiness-warnings

./scripts/kyuubiki operator-package-dynamic-smoke \
  --out tmp/operator-package-dynamic-smoke.json

Preflight checks package discovery and manifest/readiness posture. Dynamic smoke checks the executable package path. Neither replaces numerical validation.

Completion contract

  • The crate builds and its unit, malformed-input, and baseline tests pass.
  • The descriptor readiness report has no unresolved error.
  • The package manifest and implementation expose the same operator ids and entry symbol.
  • Package preflight accepts the package and dynamic smoke exercises its runtime boundary.
  • Known physical limits, tolerance basis, and validation status are visible to workflow authors.
