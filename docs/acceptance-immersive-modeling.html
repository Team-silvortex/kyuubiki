Environment and scope

The installed application used the installer-managed static frontend, a real local Orchestra service, two Rust agents, and the existing durable project store. There was no Next development server or mocked API in the native acceptance path. Node was used for frontend building and isolated browser regression only, not as an installed service.

The existing 3.2.0 native shell was reused. Updated runtime assets were built, sealed and installed through the installer; no application version was bumped. The build and installed frontend entrypoint matched at SHA-256 c77c496a48616e1cf78379d52fb6682149d0635ead658b7abb3bbc76ab89c86b. This digest identifies the entrypoint, not the complete application bundle.

All writes were isolated to the small Acceptance - immersive 3D project. Services were stopped only with no active jobs. The existing project database was not replaced. One temporary pre-acceptance runtime copy was used for rollback, then removed.

Issues found and corrected

  • Unavailable fullscreen API: WKWebView had no standard requestFullscreen. Entry now uses standard or prefixed WebKit APIs when available; otherwise it uses a reversible window-local immersive panel. Existing API rejections are still observable failures, not silently bypassed.
  • Cold-load exit recovery: a lazily loaded tool can temporarily clear React's viewport ref. Window-local fullscreen retains its owned target so exit can restore the workspace instead of failing with viewport:unavailable.
  • Default camera clipping: fitting and zooming from the top-left cropped tetrahedron nodes. CPU picking and GPU projection now share centered, proportion-preserving fitting below the title. Default presets fit the model. Drag conversion accounts for viewport scale and camera rotation; repeated focus no longer accumulates pan offsets.
  • Unexpected library overlay: entering immersive modeling from a loaded library model now opens the modeling tools instead of automatically showing the old library drawer on top of the canvas.
  • Blocked form editing: immersive guardrails previously intercepted Select All and clipboard events inside inputs. Native model-name and numeric fields now allow text editing while canvas interaction protection remains enabled.

Observed native chain

  1. PWDT loaded actual Pyodide, created a separate project, constructed a four-node, six-member truss, saved it, submitted a study and observed completed Rust-agent results.
  2. A Z-coordinate query selected only node 3 without clearing the result. The repaired viewport displayed all four nodes, and pointer picking identified the correct apex.
  3. Batch translation changed apex Z from 1.00 m to 1.25 m. Undo restored 1.00 m and redo restored 1.25 m. The shared model and viewport readout agreed.
  4. The native dock resized by keyboard in 10-pixel steps, with Home/End limiting it to 220/460 pixels. Escape restored the main interface. Library navigation exited immersive mode and displayed the real model library.
  5. Empty model names disabled Save and Save As. Select All and paste worked in the installed immersive form after the guardrail fix.
  6. Save created baseline v2 with apex Z=1.25 m while baseline v1 retained Z=1.00 m. Save As created a separate tall-variant model with four nodes and six members.
  7. The immersive Study tab submitted the tall variant successfully. After restarting the entire managed runtime and reopening the application, the saved models and versions remained available, and the reloaded variant solved to the same numeric result.
  8. The final PWDT recovery script emitted NATIVE_RECOVERY_PASS and returned Ready. Invalid negative selection indices were rejected without modifying selection or discarding results. Native layout measurement: window/panel 1432 by 821 CSS pixels; canvas stage 1062 by 710 CSS pixels. The panel filled the available WebView window.

Numerical oracle and durable receipts

Nodes are (0,0,0), (1,0,0), (0,1,0), (0,0,h). The first three are fully fixed; the apex has a -1000 N Z load. All six tetrahedron edges use E=210 GPa and A=0.01 m2. For this linear small-displacement truss, apex uz=-1000h/(EA), ux=uy=h*uz. The vertical member carries -1000 N; the two other apex members have zero axial force.

Repeatable checks and limits

PWDT setup: tests/manual/pwdt-immersive-truss3d.py. Restart/reload check: tests/manual/pwdt-immersive-recovery.py. These are frontend Python scripts, not headless-SDK implementations. The recovery script waits for mounted, measurable controls; a fixed sleep is not a reliable cold-load readiness signal.

933 workflow unit tests passed. Eleven unique related browser integration cases passed; the seven fullscreen cases were rerun after the final changes. They use Chromium with mocked storage, including API refusal, missing-API fallback, form editing, save failures, resizing, undo/redo and GPU lifecycle checks. Type checking and production build passed.

Not qualified here: Windows/Linux native WebViews, mobile native shells, large-mesh interactive frame rate, solver families beyond this linear 3D truss, or arbitrary multi-client storage failure recovery. Window-local immersive mode does not claim to enter OS fullscreen. Save still consists of existing separate metadata/version writes, not a distributed transaction. A failed or uncertain write must be inspected before retry.
