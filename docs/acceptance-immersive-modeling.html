Issues found and corrected

  • Unavailable fullscreen API: WKWebView had no standard requestFullscreen. Entry now uses standard or prefixed WebKit APIs when available; otherwise it uses a reversible window-local immersive panel. Existing API rejections are still observable failures, not silently bypassed.
  • Cold-load exit recovery: a lazily loaded tool can temporarily clear React's viewport ref. Window-local fullscreen retains its owned target so exit can restore the workspace instead of failing with viewport:unavailable.
  • Default camera clipping: fitting and zooming from the top-left cropped tetrahedron nodes. CPU picking and GPU projection now share centered, proportion-preserving fitting below the title. Default presets fit the model. Drag conversion accounts for viewport scale and camera rotation; repeated focus no longer accumulates pan offsets.
  • Unexpected library overlay: entering immersive modeling from a loaded library model now opens the modeling tools instead of automatically showing the old library drawer on top of the canvas.
  • Blocked form editing: immersive guardrails previously intercepted Select All and clipboard events inside inputs. Native model-name and numeric fields now allow text editing while canvas interaction protection remains enabled.

September 13: checkpoint consistency and recovery

This follow-up tested the complete working-model to saved-version to reloaded-model chain. Four targeted checkpoint unit cases first reproduced the pre-fix failure. The backend already provided transactional checkpoint creation; the frontend was performing an unnecessary metadata update before calling it.

  • One checkpoint write: GUI and PWDT now create an existing model's version without a preceding metadata PATCH. Model metadata, payload, latest-version pointer and new version use the backend's existing atomic checkpoint operation.
  • Save helpers preserve rejected drafts: Python ky.save_model and the browser helper send name/material in the save action instead of first changing workspace metadata. Invalid or rejected saves cannot silently rename the workspace or replace its material. Successful saves serialize matching name/material into the payload.
  • Read failure is not empty history: a failed version-list request retains known rows for the current model and publishes a model_versions recovery issue. Refresh retries the read, not the committed save. Switching models clears the old scope; delayed replies and deferred rendering cannot expose another model's version rows or overwrite its feedback.

September 13: durable checkpoint retry protocol

This is source-build, browser-mock and isolated-storage qualification, not a new native installation. The existing installed database and background services were left alone. The earlier native numerical evidence above must not be read as native acceptance of the new database revision.

  • Model and version POSTs accept an optional request_id. A successful write stores a durable, payload-free receipt in the same transaction. Identical retries return the original IDs and metadata; they do not move a newer latest-version pointer backward. Changed content returns HTTP 409. Deleting the target leaves a project-owned receipt so a stale retry cannot recreate it.
  • GUI and PWDT share an in-session retry manager. Uncertain failures and malformed successful responses retain the key; duplicate concurrent submissions share one request. A confirmed success ends the attempt, allowing later intentional saves. Backend/authentication changes, changed payloads and different parents are isolated.
  • Data revision 2 adds only receipt storage. Revision 1 is a known upgrade source, not an invitation for startup to mutate the active database. Explicit copy-upgrade preserves the baseline and source. Older trusted snapshot receipts remain verifiable.

Final workflow unit regression: 953 passed. Browser integration: 67 passed across checkpoint recovery, immersive modeling and project boundaries; the four lost-response cases exercise both GUI buttons and PWDT Save/Save As. The browser deliberately commits its mocked record before aborting the HTTP response.

Limits: the automatic frontend cache does not survive a WebView reload/close and holds at most 64 unresolved writes. It fails closed instead of silently evicting unknown outcomes. Callers needing restart recovery can retain their own explicit request ID and unchanged input. This requires a matching backend and data revision 2; older services may ignore the optional key. No PostgreSQL revision-2 run, installed-app migration, large-mesh retry benchmark or exactly-once distributed-workflow guarantee is claimed.

Usage and recovery boundaries are in the PWDT tutorial; activation and cleanup rules are in data lifecycle. Test databases are disposable; no user database or persistent backup set is created by this qualification.
