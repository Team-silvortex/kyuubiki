Tutorial 06 · Recovery

Recover without hiding partial work

Recovery starts by locating the failed stage and retaining its receipt. Do not restart the whole stack, delete local state, or resubmit a job until ownership and terminal state are known.

Classify first Retain evidence Retry one bounded stage No destructive cleanup by default

GUI recovery sequence

  1. Read the bottom event bar and copy the exact action and message.
  2. Confirm the active project and model before changing sections.
  3. Open Runtime health and the run/history view; distinguish no dispatch from a failed job.
  4. If a workflow draft failed validation, restore a full correction snapshot or fix the located item. Summary-only snapshots are not restorable.
  5. If the solve completed, retry result retrieval rather than submitting a duplicate solve.

PWDT recovery sequence

  1. Capture state, the action timeline, and the failing action id.
  2. Use the parity report to confirm that the action still exists in the current UI contract.
  3. Wait for terminal state; do not infer completion from a toast or a fixed delay.
  4. Replay only an idempotent step or a product recipe that explicitly supports resume.
  5. Keep high-risk confirmation and authority checks outside replay loops.

Headless recovery sequence

./scripts/kyuubiki headless inspect tmp/workflow.json --json
./scripts/kyuubiki headless validate tmp/workflow.json --json
./scripts/kyuubiki headless plan tmp/workflow.json --out tmp/workflow.plan.json --json
  • If validation fails, no executor should be invoked.
  • If dispatch fails before a job id, fix authority or target configuration and retain the failure report.
  • If a job id exists, query or wait on that job before creating another.
  • If a research round is partial, keep its evidence as partial and require contiguous prior evidence before the next qualified round.

Escalation packet

When bounded recovery does not work, collect one small packet instead of a whole machine dump.

  • Product version and platform.
  • Surface: GUI, PWDT, Headless, Operator SDK, orchestrated runtime, or direct mesh.
  • Project/workflow/model/job ids that are safe to disclose.
  • Validation, plan, run, watchdog, or package-preflight receipt for the failed stage.
  • Exact first failure and the bounded recovery already attempted.
  • Explicit note that credentials, local absolute paths, and unrelated user data were removed.

Stop conditions

  • Stop immediately on suspected authority drift, credential exposure, signature failure, or component-integrity mismatch.
  • Stop repeated execution when a deterministic validation or numerical failure recurs unchanged.
  • Do not clean install roots, project storage, caches, or remote state unless the Installer exposes and previews the exact cleanup action.
  • Never convert a mock, partial, stale, or recovered result into a successful research claim without requalification.
