The shortest complete path

  1. Create or select one Workbench project.
  2. Build and save one bounded model.
  3. Run it and wait for a terminal job state.
  4. Open the result and retain the run identity.
  5. Reopen the project to prove that the work persisted.
  6. Only then move to composite workflows, automation, or extension work.

Completion gate: a tutorial is not complete when a button was clicked. It is complete when the project, model, terminal run, result, and retained evidence can all be identified again.

Rules shared by every tutorial

  • Start with the smallest bounded case that can expose the full call chain.
  • Validate before execution and keep the validation result with the run.
  • Mock execution proves orchestration shape, not physical correctness.
  • A completed service run is still not research evidence until inputs, versions, metrics, and limitations are retained.
  • Do not erase a failed or partial run before its failure receipt has been captured.
  • Use project-relative paths in checked-in examples and keep machine-local credentials outside the repository.
