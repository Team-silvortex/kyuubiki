Required sequence

  1. Ingest the bootstrap documents and hard rules.
  2. Run the selected SDK preflight and require a blocker-free readiness report.
  3. Verify service health and protocol compatibility.
  4. Project only policy-allowed tools for the selected provider.
  5. Normalize one dependency frontier into a portable proposal.
  6. Build the readiness-bound Headless plan and its digest-bound approval request.
  7. Dispatch through the selected SDK bridge and retain its execution receipt.
  8. Verify the receipt and advance the digest-bound cross-turn research frontier.
  9. Retain its canonical frontier digest in caller-owned trusted storage for recovery.
  10. Observe and fetch the bound result, then verify its exact plan digest in the validation report.
  11. Attach a validated screening bundle without claiming external qualification.

Planning preflight

Rust, Python, and Elixir inspect the same bootstrap through a caller-owned resource resolver. Missing or unsafe project paths fail closed. A passing report is only none_preflight_only authority: it cannot approve, dispatch, or validate a solve.

Dependency rule

Never invent future job ids. Submit first, consume the real receipt, then plan wait and result-fetch calls in later model turns.

Native execution bridge

Rust, Python, and Elixir generate the same canonical plan digest and reject missing, stale, or payload-mismatched caller approvals before network access. The approval request has no execution authority. A caller-owned verifier authenticates approval independently of model output, and the v2 receipt retains the digest and distinguishes completed execution from partial failure. A separate caller-owned receipt verifier gates frontier advancement and preserves the real job binding across later turns. A frontier verifier separately authenticates persisted state before it can generate another call. The validation handoff then binds that state to the resolved graph, completed result, and optional screening bundle while keeping external validation mandatory.

What counts as research

A retained result must expose execution authority, provenance, validation evidence, quality gates, limitations, reproducibility, and next validation actions. A plan or real solve alone is not qualification.
