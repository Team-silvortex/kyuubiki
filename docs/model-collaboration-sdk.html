One safe flow

  • Run the selected SDK bootstrap preflight and require planning readiness.
  • Create a narrow session objective and action policy.
  • Redact context and project the authoritative Headless tools.
  • Send the request through a caller-owned model client.
  • Normalize provider calls into one portable proposal.
  • Compile the proposal into the existing Headless batch and plan.
  • Obtain exact caller approval for every gated step.
  • Dispatch through the selected SDK bridge and retain its execution receipt.
  • Verify each receipt before advancing the real-job-bound research frontier.

Owned here

  • Tool catalog projection
  • Provider response normalization
  • Context redaction and size limits
  • Policy filtering and proposal compilation

Not owned here

  • Provider HTTP clients or API keys
  • Billing, model selection, or retention policy
  • Caller approval authority
  • Rust Operator SDK authoring or PWDT GUI automation

Three peer Headless adapters

Rust, Python, and Elixir share one session policy, provider projection, canonical proposal, service/direct boundary, confirmation model, and caller-verified execution receipt. Their frontier helpers bind the returned job id across wait and result-fetch turns. Receipt and frontier verifiers remain caller-owned, along with provider clients and credentials. Their validation handoff binds the completed result to its graph and optional screening bundle without upgrading it to a qualification claim. Their shared readiness preflight checks the document and SDK resource boundary first, while retaining none_preflight_only execution authority.

Default posture

The default session exposes only service-backed actions with normal risk, limits proposals to 12 calls, and caps sanitized context at 64 KiB. Browser, sensitive, and destructive actions remain hidden until explicitly enabled. Even when enabled, Headless confirmation gates remain authoritative.

Rust Headless SDK

Projects constrained provider tools, normalizes calls, and builds an inspectable plan. Its bounded execution bridge requires exact caller approval, an independent caller-owned verifier, and retains completed or partially failed steps.

Rust Operator SDK

Accepts non-executable descriptor and schema drafts. Rust implementation, package preflight, dynamic smoke, and host admission remain mandatory.
