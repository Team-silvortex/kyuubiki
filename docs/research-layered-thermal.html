Research question and assumptions

Does a steady thermal field crossing a conductivity interface produce the expected axial expansion, independently of the chosen temperature origin? This is a verification problem before it is a material-selection problem.

QuantityDefinition
Geometry1 m long, 0.1 m high, 0.01 m thick; bonded interface at x = 0.5 m
Conductivity k, W/(m K)Moderate contrast: [10, 100]; high contrast: [2, 200]
Young's modulus E[70e9, 3e9] Pa; constant in each layer
Expansion coefficient alpha[10e-6, 20e-6] /K; constant in each layer
Thermal conditionsT(left) = Tref + rise, T(right) = Tref; other edges insulated; no sources
Mechanical conditionsLeft ux fixed; all uy fixed; no external force; Poisson ratio zero
MeshQ4 cells; nx = 2r, ny = r; r = 1, 2, 4, 8; maximum 153 nodes

The zero Poisson ratio and transverse restraint deliberately isolate an exact axial displacement reference. They do not describe a general unconstrained two-dimensional specimen. The coefficients are synthetic, not verified material cards.

Independent numerical gates

q = rise / (0.5/k_left + 0.5/k_right)
T(x) = Tref + rise - q * (min(x, 0.5)/k_left + max(x - 0.5, 0)/k_right)
ux(x) = integral from 0 to x of alpha(s) * (T(s) - Tref) ds
temperature_delta = (source_temperature - reference_temperature) * scale

The temperature profile is piecewise linear, so the displacement integral is evaluated analytically within each layer, without calling a solver. Subtraction precedes scaling and element-to-node reduction. The stress-free reference and the input temperatures must use the same origin.

For each conductivity pair, run four mesh sizes at Tref = 20 and rise = 20, then r = 8 with (Tref, rise) = (293.15, 20), (20, 0), and (20, 40). The Kelvin-shift case must preserve expansion, zero rise must produce zero expansion, and doubling the rise must double displacement.

Temperature-reference formulation references: COMSOL Thermal Expansion and MOOSE thermal expansion eigenstrain. These are formulation references, not claims that those external solvers were run.

Run through the official SDK

cargo run --locked --manifest-path sdks/rust/Cargo.toml \
  --example layered_thermal_research -- research-round-001

Run on the compute host with a reviewed, installed Orchestra and Agent. The default endpoint is http://127.0.0.1:4000. Configure KYUUBIKI_BASE_URL and, if needed, KYUUBIKI_ACCESS_TOKEN through the process environment, never a tracked file. This minimal HTTP SDK example is intended for host-local access or a trusted local transport boundary, not credential transmission over public plaintext HTTP.

The output directory must be new and its parent must already exist. Existing rounds are not overwritten. The example submits only the 14 defined cases, sequentially, with a 120-second polling deadline per case. A client timeout is not a guarantee that server work was cancelled. No fallback mock is requested.

input -> solve.heat_plane_quad_2d
      -> bridge.temperature_field_to_thermo_quad_2d
      -> solve.thermal_plane_quad_2d
      -> retain heat, bridge model, and structural outputs

The bridge contract explicitly supplies transform.reference_temperature. Its default remains zero for existing workflows that already supply temperature rise. Nonzero references on heat-load/flux fields and nonnumeric references are rejected rather than silently discarded.

Retain and interpret a round

  • Each case retains its complete request and returned result in separate JSON files.
  • report.json records relative file names, SHA-256 checksums, job ids, per-gate errors, and output-manifest/readback validation.
  • study_definition_sha256 fingerprints the runner, model and checker source. Optional KYUUBIKI_SOURCE_REVISION labels the caller's reviewed source revision; an absent value is explicitly unrecorded, never an inferred server revision.
  • Progress reports have complete: false. Only a finished matrix has complete: true; that flag alone does not mean its physics passed.
  • Any failed gate yields a nonzero process exit. Inspect the retained report rather than retrying over the same output directory.

A second result fetch tests retrieval consistency only. It does not prove persistence across a server restart or power loss. This example's report writes are not a transactional research database. Keep large raw results outside Git.

The optional thermal-patch suite contains 288 cases; all combines them with the original 14 layered cases. The default remains layered. Unknown suite names fail before any directory creation or dispatch.

AxisThermal patch values

RestraintFree expansion with rigid modes removed, or fully clamped

Free: ux = alpha * rise * x; uy = alpha * rise * y; stress = 0
Clamped: ux = uy = 0; sigma_x = sigma_y = -E * alpha * rise / (1 - nu)
Both: tau_xy = 0; heat flux = 0

This small-strain plane-stress patch prescribes a uniform thermal field at every node. It checks constitutive response and coupling, not heat-equation convergence. Displacement tolerance is 1e-10 m; stress error divided by max(E * alpha * |rise|, 1 Pa) must not exceed 1e-8. Temperature and flux tolerances are 1e-8 K and 1e-8 W/m2. Expectations are analytical, not solver-derived.

All 302 cases passed in the current-source Linux Rust engine tests. This is explicitly separate from an installed-service run. The extended service runner is compiled and its public graph contracts validated, but the 288-case suite has not yet passed through a newly installed Orchestra/Agent pair.

Expanded findings and retained evidence

First result and remaining boundary

The first installed-service round completed all 14 jobs but passed zero physical cases. Heat temperature and flux were correct; the bridge ignored the reference temperature, introducing false expansion. Even zero temperature rise gave a 0.3 mm tip displacement. A Kelvin-origin equivalent case had about 4.39725 mm displacement error. The current Rust and Elixir source now subtract the reference.

Current-source Rust regression passes all 14 cases, with separate triangle/quad bridge and corrupted-result checks. Remote Elixir contract checks also pass. The older installed remote service was deliberately not hot-patched: its failed rounds remain evidence, and an Installer-managed deployment/retest is still required.

This series does not yet establish material calibration, realistic Poisson coupling, nonlinear constitutive behavior, external-solver agreement, restart recovery, large-mesh scaling, or general mesh-convergence order. Its aligned, piecewise-linear reference is intentionally simple enough to expose semantic errors.
